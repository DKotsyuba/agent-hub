Exact registry names, upstream repository metadata, licenses, dependency relationships and available npm scripts were inspected before installation. Versions are pinned in package.json and integrity-locked in package-lock.json. No package lifecycle scripts were enabled.

Official unmodified shadcn sources and hashes are recorded separately. No generic custom component framework, backend server, runtime supervisor or state database is introduced.

WebdriverIO standalone with the Node standard assertion library provides browser checks. Standalone axe-core supplies contrast and accessibility checks; the separate axe WebdriverIO adapter was rejected because its declared peer range excludes WebdriverIO 10. No force or legacy-peer-deps override was used.

Driver downloads, browser profiles, logs and screenshots stay in the project-specific temporary directory. Driver selection is explicit; tests must not download a different browser or use the owner's browser profile.

Initial npm audit after installation reported no known vulnerabilities. This is advisory evidence, not proof of absence of unknown defects. Build/dev/test scripts execute only the prepared dependency tree.

## OpenTUI terminal dependencies

Observed 2026-11-04: the terminal package pins `@opentui/core` 0.8.2 and the same `string-width` 7.2.0 used by OpenTUI. The published package metadata matches the [upstream release](https://github.com/anomalyco/opentui/releases/tag/v0.8.2); registry integrity hashes and the complete dependency graph are recorded in `terminal/package-lock.json`. OpenTUI requires Node 26.4 or newer with `--experimental-ffi`; Node 26.13 was used locally. The core package is MIT; its platform-native package includes LGPL-2.1-or-later components. npm's full advisory check reported zero known vulnerabilities on this date, not an assurance against unknown defects. No package lifecycle scripts were enabled. Test execution uses a network-isolated environment without the user's home or credentials; artifact signing was not independently verified.

The terminal launcher and standalone compiler use [Bun 1.4.4](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.4), which satisfies OpenTUI's Bun runtime requirement. The official Linux x64 baseline archive's SHA-256 is `e0446eb55995772eb9894bebae9a6be368d985a8b9271ee124486f9946eedd76`, matching the [upstream formula](https://github.com/oven-sh/homebrew-bun/blob/main/Formula/bun.rb) on 2026-11-04; its release commit is signed, but a detached archive signature was not independently verified. The upstream project reported approximately 96,500 GitHub stars and recent releases on that date; npm download counts were unavailable. The upstream advisories for [HTTP/3](https://github.com/oven-sh/bun/security/advisories/GHSA-cf8x-9m69-3gg3) and [Brotli](https://github.com/oven-sh/bun/security/advisories/GHSA-663w-cv8g-jj2p) identify 1.4.4 as fixed. The verified archive contained one binary and no install hooks. Bun's [upstream license](https://github.com/oven-sh/bun/blob/main/LICENSE.md) and the OpenTUI platform package's bundled license files apply to redistribution. The executable includes the pinned OpenTUI assets and the separately built Rust observer; it uses the existing system services and credentials rather than packaging them.

The new standalone observer reuses the desktop's native read modules but pins Tokio 1.54.1. The desktop's existing 1.54.0 lock is yanked and affected by [RUSTSEC-2026-0384](https://rustsec.org/advisories/RUSTSEC-2026-0384.html); 1.54.1 fixes that advisory. This terminal-only choice does not change or qualify the older desktop build. The observer's exact Rust dependency graph is in `terminal/observer/Cargo.lock`.
