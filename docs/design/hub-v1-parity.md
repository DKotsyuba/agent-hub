# Hub v1 parity checklist

Paths below are relative to `/api/v1`. Check each row in the TUI and
React migration against the [API and fixture handoff](hub-v1-contract.md).

| View or action | API fields and evidence to preserve |
| --- | --- |
| All views, refresh `r`, cadence `u` | GET the visible resource. Subscribe using `/events?topic=…&interval=1\|3\|5\|10`. Show per-source outcome, producer and Hub observation times, retained stale time and coverage. Empty is an observed value. Reconnect and revalidate; retain the last good response only for the same query. |
| Navigation `0`–`4`, Enter, tabs, `z`, Esc/Back, forward, focus/scroll, help, appearance | Client state. Use stable IDs and execution selectors as navigation keys, restore the origin route, filters, focus and scroll. Standalone deep links return to the parent. |
| Overview period `p` and failed-executions link | `/overview?from&to` → `run.current`, `run.active/started/succeeded/failed/finished`, `bridge.accepted/pending/incidents`, `quota` highlights. Use each metric's `kind` and source coverage for exact, loaded/lower-bound or Unknown labels. Open `/sessions?status=failed&from&to` with the same period. |
| Overview Bridge link, incident drill-down and next page `n` | `/bridge/incidents?includeClosed=true&from&to` → `items[].id/publisher/eventId/state/createdAtMs/updatedAtMs/detail`, `page.next`, independent Bridge observation and retained coverage. |
| Sessions list, search `/`, status `t`, folder/project `p`, finished `o`, clear `x`, next page | `/sessions?status&project&q&from&to&limit&cursor` → `items[]`. Use status and clocks for live/finished, runtime/model/effort, progress and failure evidence. Literal folders use `workdir`. Label inferred project grouping with `projectInferred`; a working directory does not establish repo identity. Display loaded counts with inventory coverage. |
| Sessions Details `d`, historical and related Run links | `/sessions/:id?execution` → `session`, `lineage.match/storeFenced/pinState/selected/retainedLatest/coverage/restartResume/lineageTerminal/terminalOutcome/successCommit/cleanup`, independent link, status and sample clocks, `historyAttribution`, `answerAttribution`, usage, tools, delivery and cleanup. Selected raw status is independent of lineage outcome. |
| Sessions History, Enter to expand tools, `[`/`]` parts, beginning `i`, older `g`, latest `G` or End, follow/pause `f` | `/sessions/:id/history?execution&edge&direction&cursor` → `entries[].head/calls/results/partialBefore/partialAfter`. Use position/ID anchors, start/verified end timestamps, error, omitted bytes and attribution. Keep unmatched results distinct, legacy raw forward-only explicit, and resume separate from older browsing. |
| History footer and Details initial task proof | `/sessions/:id/initial-task?execution&cursor` → `state`, `proof.kind/root`, `storeFenced/activePin` for strict, `content` or `reason`. Current verifies the retained root. Unverified uses the retained history label and never promotes the first retained prompt to the original task. |
| Result `a` and copy `c` | `/sessions/:id/result?execution&cursor` → `content`, `proof.execution/sequence/sha256`. Assemble and verify before copy. Capability, execution and digest failures have no result text. |
| Copy/export `y` and cancel Esc | `/sessions/:id/export?execution&mode&cursor` → `boundary`, `content`, `coverage` and exact `proof`. The retained copy discloses incomplete coverage; exact preserves the one execution, store fence and active pin. Aborting copy is local. |
| Pool inventory, search, open/closed `o`, archived selection, totals and kind | `/pools?state&q&limit&cursor` → `items[].state/kind/record` and `totals.revision/retained/closed/unknown/open/completed`. Closed and completed are independent. Label loaded matches separately from source snapshot totals. Unknown kind preserves legacy presentation. |
| Pool metadata `i`, purpose `e`, proposal archive, snapshot `s` | `/pools/:id` → `pool.purposePreview/leader/revision/record`, `proposalId`, coverage. `/sections/proposals` carries the roster key, voters, criteria and reported snapshot byte length. `/content/purpose` and `/content/snapshot?proposal` return revision-fenced text. |
| Pool members/seats `m`, Enter to open Run | `/pools/:id/sections/members` → `items[].seat.profile/admission/joined`, `session`, `lineage`. Member bindings and Run proof each require the corresponding capability. A seat link alone is not a verified execution. |
| Pool discussion/chat, `g` older, `G` latest, `h` first/current edge, `f` follow, `y` copy | `/pools/:id/history?edge&direction&limit&cursor` → `format`, `upperBound`, `items[].parts/complete/valid/position/authorId/atMs` and `coverage`. Keep client anchors/unread and live resume. Export traverses one frozen retained boundary. Legacy observers explicitly offer forward-only history and lack a frozen export bound. |
| Pool decisions `d`, criteria `c`, votes `v`, deliveries `b` and section pagination | `/pools/:id/sections/:section` → discriminator, `revision/page`, optional `proposal` for proposal-related views, and section-specific `items`. Preserve validity, `checksMet/checksComplete/checksReported`, criterion evidence and delivery/replacement states. Use `formerSession` and `formerLineage` to open available original-member lineage with its identity and attribution caveats. |
| Pool completion/agreement `l`, copy record | `/pools/:id/records/:record` → `kind`. Completion has `header` including absent fields, `recordDigest`, field digests, roster, ballots, Run facts and notice. Agreement has result, proposal, roster key, seat ballots and event ID, labeled “recorded by Pool”. |
| Quota account/window views, technical toggle `d` | `/quota` → independent `status` and `snapshot`. Preserve validity interval, exhausted latch, reset, last collected sample, burn/reserve hints, advice, risk/evidence, unobserved collections and source issues. Unknown numbers stay unknown even if another account is known or exhausted. |
| Worktree project cards, startup project, technical `d`, measure again `s`, Enter to inspect and open Run | `/worktrees?project&limit&cursor` → `projects[].id/name/path/coverage` and listed `items`. `/worktrees/:id` revalidates within server inspection/cache bounds. The route has no force-probe or path input. Use per-axis `facts` state/quality/clocks, integration/activity and mtime provenance, activity clocks, hygiene, managed-record facts, warnings/probes, and related `sessions`. Show size or status lower bounds, pending facts and probe errors independently. |
